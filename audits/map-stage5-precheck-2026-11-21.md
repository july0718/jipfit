## 판정 안전 규칙

1. 원본 지번 JSON 283개의 API 3종별 수집 완전성부터 검증한다. 기존 `apis` 구형 스키마와 신규 `building_registry/closed_registry/demolition_registry` 스키마가 혼재할 수 있다.
2. **폐쇄말소대장의 코드 5(지번변경), 4(합병), 6(일부말소) 등은 원건물 멸실과 동일하지 않다.** 폐쇄말소 기록만으로 190개 원건물의 멸실을 확정하지 않는다.
3. 철거멸실관리대장 코드 1(철거)/3(멸실)과 2(부분철거)/4(부분멸실)를 구분하고, 해당 레코드가 원건물의 관리번호·동명·승인연도에 연결되는지 확인한다. 같은 지번에서 다른 동의 해체가 있었을 수 있다.
4. 현행 표제부의 주용도가 아파트이고 사용승인연도가 같더라도 **동명·건물관리번호·도로명 주소가 원래 단지와 연결되는지** 확인해야 최종 현존 판정 가능하다.
5. 최종 판정 전까지 지도 제외 상태 유지. 과거 실거래·예측·단지ID·좌표는 변경하지 않는다.
6. 원본 JSON/검증 결과는 GitHub에 무심코 게시하지 않는다. 파일 내 개인정보나 인증정보 유무를 확인한 후 공유한다.

## 다음 검증 입력

사용자 PC의 `jipfit_buildinghub_results/`에서 283개 해당 JSON을 추출해 대조하거나, 로컬 읽기 전용 분석기를 실행하여 290개 행의 `원본 파일 존재·3종 완결·관리번호/건물명/폐쇄사유/철거코드` 증거표를 생성한다.

이 단계는 **원본대장 연계 준비 및 범위 검산**이며, 최종 290개 존재·멸실 판정을 완료했다는 뜻이 아니다.
